# Serverpod Feedback Log

> **Purpose:** actionable feedback on the Serverpod SDKs, CLI, templates and docs, collected while building Plotwatch. It is the source for the hackathon's **Most Valuable Feedback** form ([Official Rules](https://tinyurl.com/SP-rules) §4: bug reports, UI improvements, suggested integrations; one form per entrant, before 14 Oct 2026, 23:59 CEST).
> **Environment:** Windows 11 Pro, Serverpod CLI 4.0.3, Flutter 3.47.5, Dart 3.13.4.
> **How to add an entry:** what happened, how to reproduce it, what was expected, and a suggestion. Add the date.

| # | Date | Area | Observation | Reproduce | Suggestion |

| F-1 | 2026-10-04 | Docs | The [quickstart page](https://docs.serverpod.dev/quickstart) uses `serverpod quickstart`, while the [upgrade guide](https://docs.serverpod.dev/upgrading/upgrade-to-four) says `serverpod create` replaces the quickstart workflow. The CLI has both (`quickstart` = `create` with defaults plus an editor prompt). | Compare the two pages with `serverpod --help`. | State in one place how the two commands relate and when to use which. |
| F-2 | 2026-10-04 | CLI / Windows | `serverpod create` on Windows prints "Updating Flutter app MacOS entitlements. failed." The rest of the setup succeeds. | `serverpod create sp_quickstart --database --auth --webapp --no-redis --no-website --ide none --no-interactive` | Skip the step on non-macOS hosts, or explain the failure. A "failed" line in an otherwise successful setup looks alarming. |
| F-3 | 2026-10-04 | Template | The fullstack template's `test/widget_test.dart` contains no tests, and its comment still says `PROJECTNAME`. `flutter test` in the Flutter package reports "No tests were found" (exit code 79). | Run `flutter test` in `<name>_flutter/` right after `serverpod create`. | Ship a minimal passing widget test (e.g. the greeting screen renders), or remove the file. Replace the `PROJECTNAME` placeholder. |
| F-4 | 2026-10-04 | CLI | After `dart test`, the embedded test PostgreSQL keeps running (6 `postgres.exe` processes). `serverpod database` only has `start`; there is no `stop`. | Run `dart test` in the server package, then check `tasklist \| findstr postgres`. | Add `serverpod database stop`, or stop the test database when the test run ends. Document what happens to the processes. |
| F-5 | 2026-10-04 | Docs / Windows | `dart install serverpod_cli` installs to `%LOCALAPPDATA%\Dart\install\bin\`, which isn't on PATH. The installation page doesn't mention it; only the installer's warning does. | Fresh Windows machine: `dart install serverpod_cli`, then `serverpod`. | Add a Windows PATH note (with the exact folder) to the installation page. |
| F-6 | 2026-10-04 | Template | The root `.gitignore` ignores the whole `.claude/` (and `.cursor/`, `.gemini/`, …) directory. That also hides project-level files teams usually commit, such as `.claude/settings.json`. | Inspect the root `.gitignore` after `serverpod create`. | Ignore only the files Serverpod generates (e.g. its skills folder and MCP config), not the whole agent directory. |
| F-7 | 2026-10-06 | CLI / embedded Postgres | When `serverpod start` ends without a clean shutdown (e.g. its terminal is closed), the embedded **development** PostgreSQL keeps running as an orphan. A later `serverpod database start` then fails with "Another process is using the local database", although nothing visible is running; the only way out is finding the process or running `pg_ctl stop` from the cached binaries by hand. | Run `serverpod start`, close its terminal window, then run `serverpod database start` in the server folder. | Detect a stale owner (its parent process is gone) and offer to stop it, or add `serverpod database stop` (see F-4). Name the PID and data directory in the error message. |
| F-8 | 2026-10-06 | Code generation | A named endpoint parameter with a default value (`{int page = 0}`) becomes a **required** parameter in the generated client and test tools (`{required int page}`); the default is silently dropped. Only nullable named parameters stay optional. | Endpoint method `Future<X> list(Session session, {int page = 0})`, run `serverpod generate`, call `client.x.list()`. It doesn't compile. | Carry the default into the generated signature, or reject the default at generation time with a message ("use a nullable parameter"). Document it in the endpoints page. |
| F-9 | 2026-10-06 | CLI / migrations | Adding a required column to an existing table makes `create-migration` stop with "One or more columns are added to table "site" which cannot be added in a table migration. The complete table will be deleted and recreated." It doesn't say **why** (a non-null column without a default), what the alternatives are (nullable, or `default=`), or whether the table has data. | Add `validatedAt: DateTime` to an existing table model, run `serverpod create-migration`. | Name the column and the reason, and suggest a nullable field or `default=`. For a table that is empty in every applied migration, `ALTER TABLE … ADD COLUMN … NOT NULL` would work without recreating it. |
| F-10 | 2026-10-08 | Flutter auth package / Android | Every Android build of an app using `serverpod_auth_idp_flutter` 4.0.3 prints: "Your app uses the following plugins that apply Kotlin Gradle Plugin (KGP): flutter_web_auth_2. Future versions of Flutter will fail to build if your app uses plugins that apply KGP." The app doesn't use `flutter_web_auth_2` itself; it comes in transitively (5.1.0) through the auth package. So every Serverpod app with auth will stop building on Android once Flutter enforces Built-in Kotlin, and app developers can't fix it themselves. | `serverpod create` with `--auth`, then `flutter run` on an Android device or emulator (Flutter 3.47.5, AGP 9.1). | Move to a `flutter_web_auth_2` version that supports Built-in Kotlin (or ask its maintainers for one), or make the dependency optional for apps that don't use web-based sign-in (only email sign-in here). Until then, mention the warning in the upgrade notes so developers know it isn't theirs to fix. |
