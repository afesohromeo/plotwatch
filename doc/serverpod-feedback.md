# Serverpod Feedback Log

> **Purpose:** actionable feedback on the Serverpod SDKs, CLI, templates and docs, collected while building Plotwatch. It is the source for the hackathon's **Most Valuable Feedback** form ([Official Rules](https://tinyurl.com/SP-rules) §4: bug reports, UI improvements, suggested integrations; one form per entrant, before 14 Oct 2026, 23:59 CEST).
> **Environment:** Windows 11 Pro, Serverpod CLI 4.0.3, Flutter 3.47.5, Dart 3.13.4.
> **How to add an entry:** what happened, how to reproduce it, what was expected, and a suggestion. Add the date.

| F-9 | 2026-10-06 | CLI / migrations | Adding a required column to an existing table makes `create-migration` stop with "One or more columns are added to table "site" which cannot be added in a table migration. | F-10 | 2026-10-08 | Flutter auth package / Android | Every Android build of an app using `serverpod_auth_idp_flutter` 4.0.3 prints: "Your app uses the following plugins that apply Kotlin Gradle Plugin (KGP): flutter_web_auth_2. So every Serverpod app with auth will stop building on Android once Flutter enforces Built-in Kotlin, and app developers can't fix it themselves. | `serverpod create` with `--auth`, then `flutter run` on an Android device or emulator (Flutter 3.47.5, AGP 9.1). | Move to a `flutter_web_auth_2` version that supports Built-in Kotlin (or ask its maintainers for one), or make the dependency optional for apps that don't use web-based sign-in (only email sign-in here). Until then, mention the warning in the upgrade notes so developers know it isn't theirs to fix. |
| F-11 | 2026-10-08 | `serverpod start` / code generation | While `serverpod start` was watching, an endpoint was saved that called a service method not written yet. The log said "Endpoint analysis skipped due to invalid Dart syntax" for `site_endpoint.dart` and `membership_endpoint.dart`, then "Code generation failed. Server not reloaded." But the client **was** rewritten (`client.dart` timestamp of that moment): it had the new enum values and **no `site` or `membership` endpoints at all**, so the running Flutter app stopped compiling. Once the service methods existed, the next saves only logged "Compiling server" (no new generation), so the broken client stayed until a manual `serverpod generate`. | With `serverpod start` running, add to an endpoint a call to a service method that doesn't exist yet and save; then add the method and save again. When the errors are gone, regenerate on the next save. Say in the log that the client was or wasn't written. |
| F-12 | 2026-10-09 | `serverpod_client` / file uploads | `FileUploader.upload` / `uploadByteData` (binary upload) can **wait forever** when the connection fails: it waits for both `stream.pipe(request.sink)` and `request.send()` (`(pipe, send).wait`), and when `send()` fails nothing reads the request body, so the pipe never completes. There is no timeout either, and the `catch` that returns `false` is never reached. In our app the capture screen spun forever. Seen when the development upload URL pointed at `localhost:8080` from the Android emulator (where `localhost` is the emulator, not the PC). | With `serverpod start`, call `createUploadDescription` (database storage) and upload from the Android emulator: the URL is `http://localhost:8080/serverpod_cloud_storage?...` and `uploadByteData` never returns. | Make the uploader fail fast: listen to the sink when `send()` throws (or send first and pipe into the started request), add a timeout option, and return `false`/throw instead of hanging. Separately: in development, build the upload URL from the request's `Host` header (or document that `publicHost` must be reachable from devices), so emulators and phones on the LAN can upload. |
| F-13 | 2026-10-12 | `serverpod start` / code generation | Same as F-11, without any syntax error: a new endpoint method (`profile.adoptLocale`, later `account.*`) was saved while `serverpod start` was running; the client was regenerated (other changes appeared) but **without the new method**, until a manual `serverpod generate`. | With `serverpod start` running, add a method to an existing endpoint and a new endpoint file in the same minute; check the generated client. | Regenerate the whole client after any endpoint change, or log which endpoints were analysed and which were skipped. |
